# 3AI 검토·승인 운영 규칙

## 목적과 적용 범위

이 문서는 ChatGPT, Claude, Gemini를 이용해 부동산 AI 프로젝트의 변경 제안·데이터 품질·모형 검증 결과를 교차 검토하는 운영 규칙을 정의한다. 중앙관리 인터페이스는 기존 부동산 분석 저장소와 분리해 운영한다.

현재 `ai-review.html`은 공개 가능한 허구 데이터로 만든 정적 시연 화면이다. 모델 API 호출, 실제 데이터 읽기, GitHub 쓰기·병합, 카카오톡 발송, 사용자 승인 기능은 연결되어 있지 않다.

## 역할과 판정 권한

- 세 모델은 같은 증거 패킷을 독립적으로 보고 주장, 근거, 반례, 미확인 항목을 제출한다.
- 1차 검토 결과는 다른 모델에게 공개하지 않는다.
- 2차 검토에는 모델명을 제거한 구조화된 의견만 제공한다. 각 모델에게 자기 제출물을 제외한 다른 의견을 보여준다.
- 오케스트레이터는 매 라운드의 익명 라벨과 실제 제공자·모델 버전의 매핑을 비공개 감사 로그에 보존한다.
- Python 판정기는 정해진 규칙을 적용하고, Edward님은 특정 패킷/변경 해시에 대해 최종 승인한다.
- AI 간 다수결은 독립적인 검증을 대체하지 않는다.

## 증거 패킷

패킷에는 요청, 변경 전후 diff, 데이터 스냅샷 ID와 기준일, 지역·기간·단위, 지표 정의, 출처 ID, 합격 기준, 검증 함수 버전, 프롬프트 및 응답 스키마 버전을 포함한다. 패킷의 canonical JSON 바이트에 SHA-256을 계산하고 모든 모델 제출 및 승인 기록에서 같은 해시를 참조한다.

원문 출처 링크와 데이터 위치를 별도로 등록한다. 모델이 만든 링크나 인용은 원문 확인 전까지 검증된 근거로 취급하지 않는다. 공개 저장소에는 민감 원자료, API 키, 개인 식별 정보를 넣지 않는다.

## 교차 검토 프로토콜

1. 1차 검토는 동일한 증거 패킷과 동일한 출력 스키마로 병렬 수행한다.
2. 결과는 claim 단위로 정규화한다. 이름, 제공자 메타데이터, 자유 서술 문체는 가능한 한 제거한다.
3. 익명 ID는 라운드마다 섞는다. 오케스트레이터는 대상 모델이 자기 결과를 받지 않도록 필터링한다.
4. 검토자는 상대 주장의 근거가 실제 결론을 뒷받침하는지, 반례가 같은 기간·지역·정의에 적용되는지 확인한다.
5. 반론·수정은 최대 2회로 제한한다. 이후에도 중요한 차이가 남으면 자동 승인하지 않고 사람 판단 대기로 넘긴다.
6. 입장 변경은 근거 ID와 변경 이유를 제출해야 한다. 설명 없는 입장 변경은 반론 해소로 인정하지 않는다.

익명화는 편향 감소 시도이며 완전한 익명성을 보장하지 않는다. 문체나 내용으로 제공자를 추측할 수 있으므로 원문을 공유하지 않고 구조화된 주장만 공유한다.

## Python 검증 경계

- 모델 출력은 JSON Schema로 검증한다. 스키마 밖 필드나 자유형 명령은 폐기하거나 `INVALID_OUTPUT`으로 기록한다.
- 검증 요청은 저장소 내 allowlist에 등록된 `validation_test_id`만 허용한다.
- 모델이 반환한 Python, SQL, 셸, URL, 파일 경로를 동적으로 실행하지 않는다.
- 허용 함수의 입력은 함수별 JSON Schema로 타입·범위 검증한다. 데이터는 읽기 전용이며 비밀정보와 쓰기 권한을 제공하지 않는다.
- 원자료가 필요한 주장은 출처 확인과 고정된 계산 결과를 별도로 기록한다. 모델 응답만으로 “재현됨” 판정을 주지 않는다.

## 상태와 차단 규칙

- `PACKET_READY`: 증거 패킷과 해시 생성 완료
- `INDEPENDENT_REVIEW`: 1차 검토 진행
- `CROSS_REVIEW`: 익명 교차 검토 진행
- `PYTHON_VALIDATION`: 스키마·근거·재현·회귀 검사 진행
- `BLOCKED_CRITICAL`: 미해결 임계 반례 또는 보안/데이터 무결성 오류
- `NEEDS_HUMAN_DECISION`: 근거 부족 또는 반박 라운드 종료 후 중요한 불일치
- `READY_FOR_APPROVAL`: 필수 근거 및 모든 자동 검증 통과
- `APPROVED`, `REJECTED`, `MERGED`: 사람 결정과 후속 반영 기록
- `STALE_APPROVAL`: 승인 후 패킷 또는 변경 diff 해시가 달라짐

미해결 임계 쟁점, 핵심 근거 미검증, 데이터 무결성 실패, 필수 회귀 검사 실패 중 하나라도 있으면 승인 가능 상태로 바꾸지 않는다. 단순 다수결로 차단을 해제하지 않는다.

## 감사와 모델 성능

로그에는 review ID, 패킷 해시, diff 해시, 모델 제공자·모델 버전, 프롬프트 버전, 원본 응답, 익명 매핑, 검증 함수 ID와 결과, 상태 전이, 사람의 결정 및 시각을 남긴다. 민감 데이터는 로그에 직접 복제하지 않고 비공개 저장소의 접근 제어된 ID로 참조한다.

모델의 성능은 검증된 주장 비율, 실제로 확인된 반례, 알려진 오류를 놓친 비율 등 사전에 정한 지표로 기록한다. 확률 예측의 Brier score 같은 확률 점수는 결과 라벨과 평가 구간이 정의된 과제에만 쓴다. 모델 성적은 참고용이며 자동 투표 가중치로 사용하지 않는다.

## 배포 구조와 보안

- GitHub Pages는 공개 가능한 요약과 검토 UI만 제공한다. 프론트엔드 코드나 브라우저 저장소에 API 키를 넣지 않는다.
- 실제 모델 호출은 보호된 서버/워크플로에서 실행한다. GitHub Actions 시크릿을 비신뢰 PR 코드에 노출하지 않는다.
- 공개 Pages의 승인 버튼은 실제 인증 백엔드가 준비되기 전에는 비활성으로 둔다.
- 실제 병합 게이트는 인증된 GitHub PR 승인 또는 인증된 서버의 해시 고정 승인 기록으로 구현한다.
- 카카오톡은 검토 요약과 인증된 검토 링크만 알린다. 채팅 메시지 자체를 승인 증거로 간주하지 않는다.
- 장애 시 자동 반영을 중단하고 직전 정상 상태를 유지한다. 긴급 외부 발행 중지 스위치와 감사 로그를 유지한다.

## 데이터 검토 기준 예시

부동산 실거래·전월세 자료의 검토는 적어도 지역, 계약 유형, 자료 기간, 기준일, 수집 범위, 정정 여부를 같은 기준으로 비교한다. 표본이 없는 달과 수집 실패를 구분하고, 가장 최근 관측치로 대체 표시할 경우 실제 기준월과 대체된 월을 명시한다. 하방위험·가격예측 모형 변경은 out-of-sample 및 point-in-time 검증, 적절한 기준모형 비교, 위기 구간별 성능을 통과하기 전 연구 상태로 둔다.
